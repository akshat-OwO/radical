# 0007: Live video stream

Use `@capgo/camera-preview@8.14.2` with Capacitor 8.5.3. Its [published API and native sources](https://github.com/Cap-go/capacitor-camera-preview) support a preview behind the WebView, QR events on the active camera session, front/rear switching, zoom, flash modes, and frame-rate queries. Its Swift package uses AVFoundation and Vision, so it works with our SPM shell. [ML Kit barcode-scanning](https://github.com/capawesome-team/capacitor-mlkit/tree/main/packages/barcode-scanning) has the scanning controls but no iOS SPM package in version 8.2.1. [Community camera-preview](https://github.com/capacitor-community/camera-preview) 8.0.2 has SPM and preview controls but lacks integrated QR detection and programmatic zoom queries. Capawesome's separate scanner requires its commercial registry. Pin the selected plugin in the manifest, catalog, and optional peer. The catalog records its minimum-release-age exception because the selected release is recent.

`internalPlugins.videoStream` is opt-in and requires `pluginOptions.VideoStream.usageDescription`. It adds camera permission only. Audio is disabled; video recording is outside this capability. The native preview fills the shell behind the WebView. The hook temporarily clears the viewfinder's ancestor backgrounds and restores their inline declarations on release. Apps keep their controls opaque and cover everything outside the viewfinder. This preserves clickable HTML controls without copying frames over the bridge. QR scanning checks at most every 500 ms; Android uses the plugin's Google Play Services ML Kit model, which can require an initial model download. iOS uses Vision.

`startVideoStream` acquires a scoped session. The scope owns the native listener and camera, or browser media tracks, video element, and detection fiber. Native acquisition is uninterruptible so stopping during startup waits for the start result before sending stop. Failed acquisition also attempts stop. `useVideoStream` holds that scope in `useBridgeAction` and serializes controls through its session queue. Stop, unmount, and provider replacement interrupt the session. Keep one stream hook active per shell because the native plugin owns a single camera session. Frame rate is reported when supported; this hook does not change recording frame rates.

Browsers use `getUserMedia`, track constraints for zoom and torch, and `BarcodeDetector` for QR detection when available. Detection is optional: a browser without that API still previews video and reports `detectionAvailable: false`. Applications can load a compatible BarcodeDetector polyfill before starting. Late media acquisitions stop their tracks after interruption. Switching releases the old camera before requesting the other facing mode. Camera absence and permission denial are typed failures; unsupported controls remain disabled through the reported state. Simulators cannot establish physical camera, torch, or optical zoom behavior.
