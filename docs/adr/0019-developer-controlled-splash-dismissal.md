# 0019: Developer-controlled splash dismissal

Apps want launch animations, such as a logo that bounces and then grows into a mask that reveals the UI. The shell cannot support them today. iOS removes the splash when WebKit finishes loading the document, which is before the app hydrates. Android loses it at the first native frame, because Capacitor's `BridgeActivity` replaces the launch theme in `onCreate`, so a blank WebView shows until the page loads. Neither platform lets the page hold or hide the splash.

The shell holds the splash and the developer decides when to hide it. Config gains `splash.dismiss: "auto" | "manual"` and `splash.timeout`. `hideSplash()` in the Plain API and `useHideSplash()` in React hide it. With `"manual"`, the splash stays up until the page calls `hideSplash()` or the timeout expires. The page draws its own launch animation behind the splash, so the shell needs no animation code. `"auto"` is the default and keeps the current behavior. Android adopts AndroidX `installSplashScreen()` in both modes, so it waits for the page as iOS does. The shell draws its own copy of the system splash, with the same color and the icon in the same 288dp box, in its first frame, then releases the system splash at once. The copy stays until the shell hides it. Holding the system splash view itself was tried first: its handover occasionally showed one frame of the app underneath. `setKeepOnScreenCondition` is not used either: it blocks the first frame, so the page could never paint under the splash and `hideSplash()` could never observe a painted frame.

## Considered Options

- Native exit animation presets, such as `hideSplash({ animation: "fade" | "zoom" | "mask" })`. Rejected: each preset needs separate Core Animation and Android implementations, and developers would get only the effects that radical ships. The iOS launch screen is a static storyboard and Android limits animated icons to about one second, so motion that starts before the page loads could not be built with presets either.
- Hiding the splash automatically when the page first paints or hydrates. Rejected: radical cannot tell when an app is ready. An app with its own loader, data fetches, or an animation that must prepare its first frame needs to choose the moment.
- No timeout in `"manual"` mode. Rejected: a broken page or a deploy that omits `hideSplash()` would leave users on the splash with no way out.

## Consequences

- `hideSplash()` waits for the images `<Splash />` draws to decode, then for two animation frames, before it calls the bridge, so the page's frame has painted when the splash disappears. Two frames alone are not enough: a configured image loads after the page first paints, and the page would show the bare background until it arrives. It resolves after the shell removes the splash, which lets the developer start an animation right after. Calls after the first do nothing. Capacitor injects the bridge before page scripts run, so no queue is needed. In a browser, and in a shell without the splash command, it does nothing.
- `splash.timeout` defaults to 10 seconds in `"manual"` mode and accepts `false` to disable it. Offline and fallback pages cannot run app code, so the shell hides the splash when one loads. That includes the service worker's fallback, which keeps the requested URL: iOS reads its `x-radical-offline-fallback` header, and Android, which cannot read document headers, checks for a marker element the worker appends to the document.
- A seamless handoff needs the page's first frame to match the splash exactly. `<Splash />` and `splashLayout()` redraw the configured image and color with each platform's geometry, from constants shared with native asset generation, so developers do not reproduce it by hand. The virtual config module imports a configured splash image as a URL, so Vite serves and emits it.
- On Android 12 and later, the system splash is a solid color with a centered icon. A gradient splash on the page has a visible seam on those versions. Developers can match the system color or animate from it.
- The splash covers native section bars on both platforms. The page controls when a bar appears with `setHidden` from sections, so a launch animation can bring it in. See ADR 0020.
- Motion before the page loads is still impossible. In remote mode on a slow network, the splash stays static until the page loads and calls `hideSplash()`.
