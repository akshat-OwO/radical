# 0010: Notification plugins and topic membership

Use Capacitor Local Notifications 8.3.1 for OS scheduling and permission, Capawesome Badge 8.0.4 for launcher badges, and Capacitor Firebase Messaging 8.5.2 for FCM tokens and push taps. Firebase Messaging provides topics on both platforms, whereas Capacitor Push Notifications alone would require a second Firebase integration. Keep Firebase opt-in so local reminders need no Firebase project.

FCM has no client API for listing subscriptions. A small native RadicalNotificationTopics plugin records successful subscriptions and unsubscriptions in installation-local persistent storage. Lookup means confirmed local membership, not an authoritative server query. Failed FCM operations leave the record unchanged. This trades server reconciliation for a useful offline lookup without adding a backend or shipping administrative credentials.

Browser reminders use the Notification API and an Effect clock. They last only while the page remains open. Validate payloads before bridge calls, reject external notification routes, and own navigation listeners in an app-wide scope. Offline taps check the route's exact-URL snapshot before adapter navigation. Firebase files remain app-owned and outside version control. Native generation copies explicitly configured files, wires APNs callbacks, and adds iOS push entitlements. Builds without those files compile but cannot verify tokens or topic delivery.
