# 0006: Files and intents

`useFilePicker` and `useIntent` follow the camera pattern from [ADR 0005](0005-camera-capability-hooks.md): manifest-declared internal plugins, Effect capabilities with typed errors, injectable browser services, and `useBridgeAction` hooks that render idle on the server and run one action at a time.

Use three pinned upstream plugins rather than writing native code: `@capawesome/capacitor-file-picker@8.1.1` for picking, `@capacitor/app-launcher@8.0.1` for URLs, and `@capacitor-community/file-opener@8.0.1` for files. Each is one manifest, because a manifest owns one bridge name. `internalPlugins.intents` enables the launcher and opener together because opening "something external" is one capability for apps. Both flags are opt-in. Neither adds permissions, but each adds native dependencies and binary size that apps without the feature should not carry.

`PickedFile` is the same shape in every runtime: name, MIME type, size, optional last-modified time, and a `Blob` with the contents. Native picks call `pickFiles` with `readData: false` and read each file through Capacitor's local file URL, like camera photos, so large files are not base64-encoded across the bridge. The native `uri` is kept so a picked file can be opened externally; browsers have none. Android omits a null name or MIME type, and iOS reports `-1` or `0` for an unknown size or date, so the manifest treats those fields as optional and the capability normalizes them: a missing type becomes `application/octet-stream`, a missing name becomes the URI's last segment, `size` is the size of the blob read back, and a non-positive date is dropped. One file with unknown metadata must not fail the rest of a selection. Native results with no files, and the picker's `pickFiles canceled.` rejection, become `Cancelled`. That plugin rejects cancellation with a message and no code, so the message is matched exactly for the pinned version. The browser fallback is a hidden file input shared with camera, with `accept` and `multiple` mapped from the options.

`openUrl` parses the URL first and fails with `Unavailable` before any native call when it is invalid. The launcher reports `completed: false` when nothing handled the URL; that becomes `NoHandler`. `openFile` needs a native URI. The opener's code `8` (no activity or preview) becomes `NoHandler` and code `9` (missing file) becomes `Unavailable`; other codes stay `BridgeCallFailed`. Its numeric codes are not manifest identifiers, so they are mapped in the capability, as camera's codes are. The default handler is `openWithDefault: true`: Android's default app, or the system "Open with" sheet when several apps qualify, and an iOS Quick Look preview that resolves when it closes. `chooser: true` asks for the Android chooser or the iOS Open In menu. Browsers open URLs with `window.open` and `noopener`, which cannot report a blocked popup, and cannot open files externally.
