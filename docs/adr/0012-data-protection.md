# 0012: Data protection and web data clearing

Use an opt-in radical-owned native plugin, `RadicalDataProtection`, enabled by `internalPlugins.dataProtection`. Keeping the small native templates in radical lets clearing also remove radical's saved offline URL and transition overlays. Separate screen-security and cache-clearing dependencies would still require this shell integration and add optional peers. No new JavaScript native dependency is needed.

`setDataProtection` returns the enabled policy and separate screenshot, recording, and app-switcher capabilities. Android sets [FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE). iOS adds an opaque window cover before resigning active and while [UIScreen reports capture](https://developer.apple.com/documentation/uikit/uiscreen/captureddidchangenotification). It reports screenshots as unsupported. Capture obscuring is reactive, so initial recording frames may escape. We avoid reparenting WebViews into undocumented secure text-field internals. Browsers report every protection field false. Protection persists across hook unmounts until explicitly disabled or the shell process ends.

`clearWebData` first disables native snapshot reporting, asks every radical worker version to stop writes and drain pending cache writes, unregisters workers, and deletes origin Cache Storage, including assets, snapshots, and any cached offline manifest. A cleared controller stays disabled until navigation. Native clearing then removes WebView website data, cookies, native HTTP caches, app cache and temporary files, saved offline URLs, and retained transition overlays. Android uses WebStorage, CookieManager and WebView clearing APIs. iOS uses the WebView's actual WKWebsiteDataStore, URLCache and HTTPCookieStorage. Cache directory traversal runs off the UI thread. Packaged assets and the build's immutable manifest remain installed.

The Effect API uses an injectable BrowserDataProtection service and Live layer. Browser exceptions, worker acknowledgement timeouts, IndexedDB errors and blocked deletion become WebDataClearFailed. Native failures retain their typed bridge errors. useDataProtection uses useBridgeAction for SSR safety and one operation at a time.

Callers must stop application writes, close IndexedDB connections and other tabs, and avoid concurrent worker registration before clearing. Deletion is not an origin-wide transaction. Browsers can erase only accessible data: localStorage, sessionStorage, visible cookies at current path and parent-domain scopes, discoverable IndexedDB databases, and Cache Storage. JavaScript cannot erase HttpOnly cookies, other origins or storage partitions, hidden cookie paths, browser HTTP disk caches, or databases when enumeration is unavailable. Native WebView APIs cover HttpOnly cookies and website caches across its data store. Neither platform can recall screenshots already saved by the user, and clearing is not server-side logout. Failures must be handled; they do not certify that all data was removed.

Notification taps read the same origin Cache Storage snapshots that clearing deletes, across app IDs and build versions. Notifications currently persist no additional browser notification or topic state. Clearing localStorage and sessionStorage also covers any app-owned notification state there. Native clearing removes Radical's installation-local notification topic membership record from SharedPreferences on Android and UserDefaults on iOS, even when the notifications plugin is disabled. Stop in-flight topic operations before clearing so their completion cannot recreate the record.

Clearing does not unsubscribe from FCM topics, delete push tokens, or cancel OS-scheduled notifications. Those operations change delivery outside web storage and require separate notification APIs, permission, or Firebase connectivity. Unsubscribe from known topics before clearing if delivery must stop. The local membership record is only a history of successful operations, so an empty record after clearing does not mean Firebase has no subscriptions.

`core/offline/offline-protocol.ts` owns the snapshots-disabled property, clear command, success and failure acknowledgements, and snapshot-ready message. Worker commands and browser acknowledgements decode through its Schema literal union. Unknown and unrelated messages are ignored; they neither clear data nor acknowledge success. The document-start snapshot listener uses a decoder projected from the same finite Schema union. Native generation renders saved-URL preference keys from this module into both shell and clearing templates.
