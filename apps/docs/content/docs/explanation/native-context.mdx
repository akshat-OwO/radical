Server rendering needs platform and safe-area data before the bridge runs. Waiting for a JavaScript call would render browser defaults first and move content after hydration.

## Hydration and live insets have different owners

Bundled rendering starts with CSS `env()` values and stable browser context. TanStack's SSR-disabled shell skips its loader; absent loader data also produces browser styles. `mountNativeContext` hands live CSS values to the shell after mount, without changing React's initial style props.

Insets describe system UI boundaries, not keyboard height. The framework still owns rendering and route data.

<Callout type="warning" title="Presentation data is untrusted">
  Any client can send the cookie or header. Schema validation proves shape, not
  identity. Malformed context falls back to browser values; authorization needs
  your app's authentication.
</Callout>

[Server reference](/docs/reference/server) describes parsing. [Safe-area reference](/docs/reference/safe-area) covers CSS and subscriptions.
