---
title: "Remote and bundled modes"
description: "Why UI delivery changes requests, startup, and offline behavior."
---

Remote mode keeps the server as the document origin. Bundled mode moves the UI into the shell and keeps data on an API origin. That choice changes startup and the browser's request boundary.

<Mermaid
  title="Remote documents and bundled API requests"
  chart={`flowchart TD
    subgraph Remote
        R[Remote WebView] -->|HTTP document, fetch, or form with radical-context cookie| S[Framework server]
        S -->|Server-rendered HTML and data| R
    end
    subgraph Bundled
        L[Packaged SPA on local shell origin] --> F[createRadicalFetch]
        F -->|Eligible local or API URL rewritten to config.origin| C[Credentialed CORS request with x-radical-context]
        C --> W[withBundledRequests]
        W -->|Allowed OPTIONS: 204 CORS response| L
        W -->|Other requests| M[createRadicalRequestMiddleware]
        M --> A[Start handler and API]
        A -->|Response through wrapper, CORS and exposed headers| L
    end
`}
/>

The bundled origins are `https://localhost` on Android and `capacitor://localhost` on iOS. Global fetch, HTML forms, third-party origins, and ordinary browsers retain normal request behavior. Only `createRadicalFetch` routes eligible shell requests.

## Startup follows the UI location

| Choice | Remote | Bundled |
| --- | --- | --- |
| UI update | Deploy server documents | Repackage native UI assets |
| First offline launch | Packaged fallback | Packaged SPA; loaders must tolerate API failure |
| Visited offline route | Exact-URL HTML snapshot | App-owned data strategy |
| Worker and launch gate | Remote worker; Android launch gate | Omitted |
| iOS App-Bound Domains | Enabled | Omitted |

Packaging HTML does not make remote data available offline.

## CORS grants access, not identity

The wrapper grants credentialed CORS only to the two local origins. Start's middleware permits those origins through server-function CSRF checks and retains checks for other callers. Neither authenticates requests.

The TanStack wrapper exposes `x-tss-serialized`, `x-tss-raw`, and `x-tss-error`. Core `withBundledRequests(handler, outputs?)` exposes no headers unless supplied with adapter outputs. Without those headers, bundled Start clients cannot read the response protocol.

<Callout type="warning" title="Authentication remains app-owned">
  Cross-site WebView cookie restrictions still apply. Use HTTPS and a compatible
  authentication design. Native context cannot authorize a request.
</Callout>

[Switch to bundled mode](/docs/guides/bundled-mode) contains the setup steps. The [bundled-mode decision](https://github.com/akshat-OwO/radical/blob/main/docs/adr/0004-bundled-mode.md) records the request contract.
