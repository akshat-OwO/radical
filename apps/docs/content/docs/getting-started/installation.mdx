Create an app that displays device information. The setup below uses the same APIs as Radical's [example app](https://github.com/akshat-OwO/radical/tree/main/apps/example), without changing your existing pages or add-ons.

## Prerequisites

Install Node.js 22.18 or later and a package manager. The examples use pnpm. Check your tools:

```sh
node --version
pnpm --version
```

You need React and TypeScript knowledge to change the app. Android Studio and Xcode are optional until [the native step](/docs/getting-started/native).

The package is `@akshatowo/radical`. The CLI command is `radical`.

## Create a TanStack Start project

Use the CLI from TanStack's [Getting Started guide](https://tanstack.com/start/latest/docs/framework/react/getting-started):

```sh
npx @tanstack/cli@latest create
```

Choose a project name, TanStack Start with React, and Vite. Select any package manager and add-ons you want, including Tailwind, shadcn, Neon, and devtools. Use Start rather than the router-only option.

Enter the generated project directory. If you skipped dependency installation, install dependencies now. The commands below use pnpm. Use your chosen package manager's equivalents.

Keep the generated routes, stylesheets, dependencies, and package scripts. Follow each add-on's setup instructions, including environment variables for database and authentication integrations.

With TanStack CLI 0.72.0, the generated Neon demo uses an older server-function API. If type checking reports that `inputValidator` does not exist in `src/routes/demo/neon.tsx`, change `.inputValidator(...)` to `.validator(...)`. Keep the validation callback. See [TanStack server-function validation](https://tanstack.com/start/latest/docs/framework/react/guide/server-functions#basic-parameters).

## Add Radical

Install Radical:

```sh
pnpm add @akshatowo/radical@0.2.0
```

Effect is a required peer dependency. pnpm, npm 7+, and Bun install it automatically. Yarn Berry users run `yarn add effect` once because Yarn warns about missing peers instead of installing them. The Plain API needs no `effect` imports. See the [Effect API](/docs/guides/effect-api) to compose Effects directly.

If pnpm reports an ignored build script for `sharp`, run `pnpm approve-builds` and approve `sharp`. Radical uses it to generate native assets.

### Configure Vite

Add these imports and the Radical config to `vite.config.ts`:

```ts
import {
  radical,
  tanstackStartOptions,
} from "@akshatowo/radical/tanstack-start";
import type { RadicalConfig } from "@akshatowo/radical/vite";

const config = {
  appId: "dev.example.myapp",
  name: "My app",
  mode: "remote",
  devHost: "localhost",
} satisfies RadicalConfig;
```

If the generated file already names its Vite configuration `config`, rename that binding and its default export to `viteConfig`.

In the existing plugins array, pass the Radical options to `tanstackStart` and add `radical(config)`:

```ts
plugins: [
  // Keep existing plugins here, including Tailwind, devtools, and database plugins.
  tanstackStart(tanstackStartOptions(config)),
  radical(config), // [!code ++]
  viteReact(),
],
```

Keep the generated React plugin's name and place it after Start. If `tanstackStart` already has options, spread `...tanstackStartOptions(config)` into that object. Merge its `spa.enabled` value into any existing `spa` options. Keep the other Start options. Remote mode loads the UI from the development server. `devHost` tells the native shell which host to connect to.

### Include generated plugin types

Append `.radical/plugins.d.ts` to the existing `tsconfig.json` include list. Keep all existing entries and compiler options. For example:

```json
{
  "include": ["**/*.ts", "**/*.tsx", ".radical/plugins.d.ts"]
}
```

Add `.radical/` to the generated `.gitignore`.

### Register request middleware

If `src/start.ts` does not exist, create it:

```ts
import { createStart } from "@tanstack/react-start";
import { createRadicalRequestMiddleware } from "@akshatowo/radical/tanstack-start-server";

export const startInstance = createStart(() => ({
  requestMiddleware: [...createRadicalRequestMiddleware()],
}));

declare module "@tanstack/react-start" {
  interface Register {
    config: Awaited<ReturnType<typeof startInstance.getOptions>>;
  }
}
```

If `src/start.ts` already exists, add the middleware import and prepend `...createRadicalRequestMiddleware()` to its existing `requestMiddleware` array. Keep the other middleware, Start options, and module registration. Add the `Register.config` declaration above if it is missing. Use your existing Start instance export in that declaration.

The middleware supplies typed native context to server functions and SSR. Keep the whole middleware list so Start's server-function CSRF checks stay enabled.

If `src/server.ts` does not exist, create it:

```ts
import {
  createStartHandler,
  defaultStreamHandler,
} from "@tanstack/react-start/server";
import { offlineHandler } from "@akshatowo/radical/tanstack-start-server";

export default {
  fetch: createStartHandler(offlineHandler(defaultStreamHandler)),
};
```

If `src/server.ts` already exists, import `offlineHandler` and wrap the SSR callback passed to `createStartHandler`. For example, change `createStartHandler(defaultStreamHandler)` to `createStartHandler(offlineHandler(defaultStreamHandler))`. Wrap a custom SSR callback the same way. Keep the surrounding request handler and exports. `offlineHandler` wraps the SSR callback, not the exported `fetch` handler.

This keeps Start's streaming SSR handler and adds route-level offline response headers. Offline routes remain opt-in.

### Add the root loader and provider

Edit `src/routes/__root.tsx`. Keep the existing document, head links, stylesheets, header, and devtools.

Add these imports:

```tsx
import { createServerFn } from "@tanstack/react-start";
import { safeAreaStyle } from "@akshatowo/radical/client";
import { RadicalProvider } from "@akshatowo/radical/react";
import type { CSSProperties } from "react";
```

Add a server function above the root route:

```tsx
const readNativeContext = createServerFn({ method: "GET" }).handler(
  ({ context }) => context.nativeContext
);
```

Add a loader to the existing `createRootRoute` or `createRootRouteWithContext` options:

```tsx
loader: async () => ({ nativeContext: await readNativeContext() }),
```

If the root already has a loader, keep its work and add `nativeContext: await readNativeContext()` to its returned object. Keep any existing loader data.

Inside the existing shell component, before its `return`, add:

```tsx
const { nativeContext } = Route.useLoaderData();
const rootStyle: CSSProperties & ReturnType<typeof safeAreaStyle> =
  safeAreaStyle(nativeContext, "remote");
```

Add `style={rootStyle}` to the existing `<html>` element. If it already has a style, merge the objects with `style={{ ...existingStyle, ...rootStyle }}`. Keep its other attributes.

Inside the existing body, wrap `{children}` with the provider:

```tsx
<RadicalProvider nativeContext={nativeContext}>{children}</RadicalProvider>
```

You can also include the existing header, footer, and devtools inside the provider if they use Radical hooks. Keep `<Scripts />` and the rest of the shell.

Append `viewport-fit=cover` to the existing viewport meta content in `head`:

```tsx
{
  name: "viewport",
  content: "width=device-width, initial-scale=1, viewport-fit=cover",
},
```

Keep the other meta entries and head links, including the generated stylesheet link. The root loader supplies the same native context during SSR and hydration.

`safeAreaStyle` supplies the CSS variables `--radical-safe-area-top`, `--radical-safe-area-right`, `--radical-safe-area-bottom`, and `--radical-safe-area-left`. Optionally use them in your stylesheet or Tailwind arbitrary values to pad content around system bars. For example:

```css
main {
  padding-top: calc(var(--radical-safe-area-top) + 16px);
  padding-right: calc(var(--radical-safe-area-right) + 16px);
  padding-bottom: calc(var(--radical-safe-area-bottom) + 16px);
  padding-left: calc(var(--radical-safe-area-left) + 16px);
}
```

### Register the offline worker

Register the worker from the client entry instead of a React effect. Create `src/client.tsx`, or add the registration to your existing client entry:

```tsx
import { registerOffline } from "@akshatowo/radical/client";
import { StartClient } from "@tanstack/react-start/client";
import { startTransition, StrictMode } from "react";
import { hydrateRoot } from "react-dom/client";

startTransition(() => {
  hydrateRoot(
    document,
    <StrictMode>
      <StartClient />
    </StrictMode>
  );
});

const register = () => {
  void registerOffline({
    mode: "remote",
    production: import.meta.env.PROD,
    base: import.meta.env.BASE_URL,
  });
};

if (document.readyState === "complete") {
  register();
} else {
  window.addEventListener("load", register, { once: true });
}
```

TanStack Start picks up `src/client.tsx` automatically. The entry runs once in the browser, so StrictMode and navigation cannot repeat registration. Waiting for `load` keeps worker installation from competing with the initial page load.

### Add a device route

Create `src/routes/device.tsx`. Keep your existing home page:

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { useDeviceInfo } from "@akshatowo/radical/react";

const Device = () => {
  const device = useDeviceInfo();

  return (
    <main>
      <h1>My app</h1>
      <pre>
        {device.loading
          ? "Loading device info..."
          : JSON.stringify(device.error ?? device.value, null, 2)}
      </pre>
    </main>
  );
};

export const Route = createFileRoute("/device")({ component: Device });
```

### Add the offline fallback

Create the `public` directory if it does not exist. Add `public/offline.html` as a standalone document with no external assets:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Connection unavailable</title>
  </head>
  <body>
    <h1>Connection unavailable</h1>
    <p>Connect to the internet, then <a href="/">try again</a>.</p>
  </body>
</html>
```

## Run in the browser

Start the development server from your project directory:

```sh
pnpm dev
```

Open `/device` at the URL printed by Vite, for example `http://localhost:3000/device`. You see **My app** and device information with `platform: "web"`. The hook reports loading during SSR and reads browser information after mount.

Keep the server running. In a second terminal, check the app:

```sh
pnpm exec tsc --noEmit
pnpm build
```

Run the server once before type checking so Start generates `src/routeTree.gen.ts`. Use `pnpm exec tsc --noEmit` if your template has no typecheck script. Production builds generate offline assets; service worker registration stays disabled during development.

Continue with [project structure](/docs/getting-started/project-structure) or [run on Android or iOS](/docs/getting-started/native).
