## Config

`navigation.sections` declares 2 to 5 sections in order. The first section is the start section.

| Field | Value |
| --- | --- |
| `id` | Unique, nonempty string |
| `title` | Nonempty string |
| `route` | Unique absolute path, without a query, fragment, or trailing slash except `/` |
| `icon` | `{ ios: "house", android: "./assets/home.svg" }` |
| `selectedIcon` | Optional icon pair with the same shape |

`ios` names an SF Symbol. `android` names an SVG file relative to the app root. Shell builds consume these declarations for native navigation. Android generation converts both icon appearances to VectorDrawables. Invalid or unsupported SVGs fail generation with `InvalidAsset` before replacing the previous shell.

Validation returns `InvalidConfig` with the bad field's path. Section declarations appear in `virtual:radical/config`, the build plan's `navigation`, and `radical-manifest.json` under `navigation`.

## React

`TanStackSections` is exported from `@akshatowo/radical/tanstack-start-client` and its Effect equivalent. It connects one router to section state and supplies the hook's context. It accepts `router`, `sections`, and `children`, and belongs under `RadicalProvider` around the route outlet.

```tsx
import { useRouter } from "@tanstack/react-router";
import { useSections, useWindowLayout } from "@akshatowo/radical/react";
import { TanStackSections } from "@akshatowo/radical/tanstack-start-client";
import { config } from "virtual:radical/config";

function SectionLayout({ children }) {
  const router = useRouter();
  return (
    <TanStackSections router={router} sections={config.navigation.sections}>
      <Navigation />
      {children}
    </TanStackSections>
  );
}

function Navigation() {
  const { sections, active, hidden, select } = useSections();
  const { widthClass } = useWindowLayout();
  if (hidden) return null;
  return (
    <nav
      style={{
        display: "flex",
        flexDirection: widthClass === "compact" ? "row" : "column",
      }}
    >
      {sections.map((section) => (
        <button
          key={section.id}
          aria-current={active?.id === section.id ? "page" : undefined}
          onClick={() => void select(section.id)}
        >
          {section.title} {section.badge}
        </button>
      ))}
    </nav>
  );
}
```

Radical ships no styled navigation component. The example app places its web bar at the bottom on compact windows and a rail on medium and expanded windows.

| `useSections()` field | Behavior |
| --- | --- |
| `sections` | Ordered declarations, each with `badge`, initially `null` |
| `active` | Active section or `null` |
| `hidden` | `true` when no section is active |
| `select(id)` | Returns a Promise. Restores an inactive section's last URL or its root if unvisited. Selecting the active section returns to its root. |
| `setBadge(id, value)` | Returns a Promise. Accepts a finite number, a string of 1 to 4 characters, or `null` to clear. Badges are held in memory and never persisted. |

`InvalidSection` is exported from both React entry points. Unknown ids, invalid badges, and actions without a provider fail with `InvalidSection`. Without a provider, the hook returns empty sections and `hidden: true`.

## Routing

A section owns its root path and descendants at path segment boundaries. The longest matching prefix wins. `/inbox` owns `/inbox/message`, but not `/inboxes`. The TanStack adapter builds each declared internal destination once, then applies its `caseSensitive` setting. Declarations use the same internal coordinates as `location.pathname` and `location.href`, without the basepath or custom output rewrite found in `publicHref`. Declaration normalization does not apply browser input rewrites. The router's trailing-slash policy does not change prefix ownership. Matching defaults to case-insensitive in TanStack. Encoded and decoded non-ASCII declarations match the same pathname, including mixed encoding. Reserved escapes such as `%2F` stay encoded, as in the router. Original declarations remain available as navigation destinations. Literal trailing slashes other than `/`, repeated slashes, and dot segments are rejected by config validation. Percent-encoded dot segments are also rejected because URL processing can collapse them. Query strings and fragments do not affect ownership. Memory preserves the complete URL, including both.

Routes outside every section hide the bars. `staticData: { radical: { navigation: "hidden" } }` also hides the bars and reports `active: null`, including on descendants. Direct links and history update section memory after the router resolves.

Section selection disables transitions. With `browserTransitions(router)` installed, direct navigation between different sections also skips browser and native transitions. Navigation within a section keeps its route transition.

## Effect API

`@akshatowo/radical/effect/react` exports `useSections()` with the same state and Effect-returning `select` and `setBadge`.

`@akshatowo/radical/effect/client` exports `makeSections`, `Sections`, `sectionsLayer`, `selectSection`, and `setSectionBadge`. `makeSections(sections, initialLocation, navigate, initialHidden?, ownership?)` creates an isolated controller. `initialLocation` and `controller.update(location, hidden?)` take `{ href, pathname }`: the complete URL for memory and the decoded pathname for ownership. `sectionOwnership(sections, caseSensitive = true, normalizePathname?)` compiles an ownership matcher, preserving the original declarations. The default normalizer leaves paths unchanged. The TanStack adapter supplies a matcher compiled with its internal destination builder and case setting to both the controller and transition checks. `controller.subscribe(listener)` returns cleanup. `sectionsLayer(controller)` supplies the `Sections` service to the two action Effects.

`@akshatowo/radical/effect/tanstack-start-client` also exports `tanstackSections(router, sections)`. It exposes `{ controller, mount }` for non-React consumers. `mount` requires `Bridge` and returns cleanup. React's `TanStackSections` owns that lifecycle.

## Shell bridge contract

The section controller also works in browsers and shells without native navigation.

The adapter sends `RadicalNavigation.update` with `{ sections, active, hidden }` on mount and state changes. Entries include badges. Shells without this command can ignore it. Shells draw bars only when `hidden` is false.

Shells send a `radicalSectionSelect` event with `{ id }` for each selection intent. Selection events must not be retained or replayed. The adapter performs the route change. Invalid payloads and unknown ids are ignored. Route memory and badge state stay in the web app's single controller.

## iOS shell

Configuring sections enables native navigation and sets the generated app's minimum deployment target to iOS 18. Apps without sections keep iOS 15. Build with the iOS 27.1 SDK for iPhone Duo support.

The shell uses `UITab` with sidebar-adaptive placement. UIKit places a bottom bar on iPhone, a sidebar on iPad and the Duo's inner display, and a vertical bar on its outer display. The sidebar opens at launch in regular-width landscape windows, where it tiles beside the page. Narrower windows start with UIKit's tab bar, and the sidebar opens as a dimming overlay. Users can collapse or reopen it. SF Symbols come from `icon.ios`; `selectedIcon.ios` supplies the selected variant. `setBadge` updates the native badge, and `null` clears it.

The shell retains one WebView, which never changes parents. The page draws edge to edge, under the status bar and behind the Liquid Glass bars. Bar space reaches the page through the existing safe-area CSS variables and native context. Apply `safeAreaStyle` or those variables to page content so controls stay clear of the bars while backgrounds extend under them.

Declarations are compiled into the shell. Bars are present before the web app mounts, including bundled and offline launches. Once mounted, `TanStackSections` updates selection, visibility, and badges. Routes outside sections and routes marked `navigation: "hidden"` hide the native controls.

Apps that draw browser navigation should omit their web controls when their native context has `platform: "ios"` or `platform: "android"`. Keep `TanStackSections` mounted so native selection intents still reach the router. Bundled apps read `localNativeContext()` after hydration because the packaged HTML has browser context. The example app uses `useSyncExternalStore` to preserve the first render and then read the shell platform.

## Android shell

Configuring sections adds Material Components 1.14.0 and a Material 3 theme to the generated Java shell. Apps without sections keep their existing theme and dependencies.

`BottomNavigationView` draws the controls below 600 CSS pixels. `NavigationRailView` draws them at medium and expanded widths. Rotation, resizing, and folding update placement without recreating or reparenting the WebView. WindowManager supplies the separating hinge bounds. A vertical hinge bounds controls to the left pane. A horizontal hinge bounds the rail to the upper pane and the bottom bar to the lower pane.

The WebView keeps its window-sized CSS viewport. The shell clips the bar area and publishes that space through native-context safe-area insets and the existing CSS variables. Page content uses `safeAreaStyle` or those variables, including while the keyboard is visible.

`icon.android` and `selectedIcon.android` name SVG files relative to the app root. The selected icon defaults to `icon.android`. Conversion supports paths, basic geometry, and transforms. `currentColor` becomes black before conversion so Material's item tint supplies the control color. Unsupported VectorDrawable elements and attributes fail generation. Drawable filenames use section indices, independent of section ids.

Selection sends an intent and waits for the adapter's state. Tapping the active section still sends an intent to return to its root. Route changes select the matching item without emitting an intent. Number badges use Material's nonnegative integer count display, strings use text badges, and `null` removes the badge. Hidden routes remove both bars and their insets.

Section declarations are compiled into the shell, so bars exist before bridge registration in remote, bundled, and offline launches. `TanStackSections` remains mounted to update route selection, badges, and visibility.
