</Callout>

## Config

- `navigation.sections` enables section navigation.
- Native bars are the default on both platforms.
- It accepts 2 to 5 sections in display order.
- The first is the start section.

```ts
const navigation = {
  sections: [
    {
      id: "home",
      title: "Home",
      route: "/",
      icon: { ios: "house", android: "./assets/home.svg" },
    },
    {
      id: "inbox",
      title: "Inbox",
      route: "/inbox",
      icon: { ios: "tray", android: "./assets/inbox.svg" },
    },
  ],
};
```

| Field | Constraints |
| --- | --- |
| `id` | Unique string with non-whitespace text |
| `title` | String with non-whitespace text |
| `route` | Unique absolute path. No query, hash, whitespace, backslash, repeated slashes, or dot segments, including percent-encoded dots. No trailing slash except `/`. |
| `icon` | `{ ios, android }`: SF Symbol name and app-root-relative SVG path |
| `selectedIcon` | Optional icon pair. Defaults to `icon`. |

- Invalid declarations return `InvalidConfig` with the field path.
- Android converts SVGs to VectorDrawables.
- Paths, basic geometry, and transforms are supported. `currentColor` uses Material's item tint.
- Unsupported SVGs fail generation with `InvalidAsset` before replacing the shell.

## Bar and Android theme

`navigation.bar` chooses who draws the bar on each platform.

| Option | Values | Default |
| --- | --- | --- |
| `bar.ios`, `bar.android` | `"native"`, `"web"` | `"native"` |
| `android.labels` | `"labeled"`, `"selected"`, `"unlabeled"` | `"labeled"` |
| `android.colors.container` | Color | Material container |
| `android.colors.indicator` | Color | Material active indicator |
| `android.colors.badge` | Color | Material badge background |
| `android.colors.icon.selected`, `.unselected` | Color | Material icon tint |
| `android.colors.label.selected`, `.unselected` | Color | Material text color |

- A Color is `"#RRGGBB"`, `"#AARRGGBB"`, or `{ light, dark }` with either hex format.
- Alpha comes first.
- Light and dark values follow system night mode.
- Omitted colors keep Material 3 defaults on both the bottom bar and rail.
- Invalid values return `InvalidConfig` with the field path.

```ts
const navigation = {
  sections,
  bar: { ios: "native", android: "web" },
  android: {
    labels: "selected",
    colors: {
      container: { light: "#EDE4FF", dark: "#241538" },
      indicator: "#80553A78",
      icon: { selected: { light: "#3D1963", dark: "#F0DBFF" } },
    },
  },
};
```

- With `"web"`, the shell creates no bar or rail.
- The page keeps the full window and safe-area insets describe only system bars.
- Sections, selection, badges, iOS edge swipe, and Android predictive back still work.
- Android theme options apply only with `"native"`.

## React

`TanStackSections` connects one router to section state. It accepts `router`, `sections`, and `children` under `RadicalProvider`, around the route outlet.

```tsx
import { useRouter } from "@tanstack/react-router";
import { TanStackSections } from "@akshatowo/radical/tanstack-start-client";
import { config } from "virtual:radical/config";

function SectionLayout({ children }) {
  const router = useRouter();
  return (
    <TanStackSections router={router} sections={config.navigation.sections}>
      {children}
    </TanStackSections>
  );
}
```

`useSections()` from `@akshatowo/radical/react` supplies state and actions for custom web controls. Radical has no styled navigation component.

| Field | Behavior |
| --- | --- |
| `sections` | Ordered declarations with `badge`, initially `null` |
| `active` | Active section or `null` |
| `native` | `true` when the shell draws the section bar. `false` in browsers, web-bar mode, or without sections. Uses provider native context for SSR and hydration. |
| `hidden` | `true` when no section is active |
| `select(id)` | Promise. Restores an inactive section's last URL, or its root if unvisited. Selecting the active section returns to its root. Replaces the history entry. |
| `setBadge(id, value)` | Promise. Accepts a finite number, a string of 1 to 4 characters, or `null` to clear. Badges stay in memory. |

Unknown ids, invalid badges, and actions without a provider fail with `InvalidSection`, exported from both React entry points. Without a provider, state is `{ sections: [], active: null, hidden: true, native: false }`.

- Custom web controls must respect `hidden`.
- Web controls render when `useSections().native` is `false`. `TanStackSections` must stay mounted to handle native selections.
- Bundled apps read `localNativeContext()` after hydration to preserve the browser context used by the first render.

## Routing

| Rule | Behavior |
| --- | --- |
| Ownership | Longest path prefix at a segment boundary. `/inbox` owns `/inbox/message`, not `/inboxes`. `/` owns all paths unless a longer prefix matches. |
| TanStack paths | Internal paths, as in `location.pathname` and `location.href`, without the basepath or output rewrite in `publicHref`. Input rewrites do not apply to declarations. |
| Matching | Uses the router's `caseSensitive` option, default `false`. Trailing-slash policy does not change ownership. Encoded and decoded non-ASCII paths match. Reserved escapes such as `%2F` stay encoded. |
| Query and hash | Do not affect ownership. Section memory keeps both. Direct links and history update memory after navigation resolves. |
| Hidden routes | Unowned routes and `staticData: { radical: { navigation: "hidden" } }` hide controls and set `active: null`. The setting applies to descendants. |
| Transitions | Section selection disables transitions. With `browserTransitions(router)`, direct navigation across sections also skips transitions. Within a section, route transitions apply. |

System back follows the [back rules](/docs/reference/transitions#system-back).

## Native controls

Section declarations compile into the shell, so controls appear before mount in remote, bundled, and offline launches. After mount, `TanStackSections` updates selection, visibility, and badges.

| Platform | Placement and requirements |
| --- | --- |
| iOS | Bottom bar on iPhone, sidebar on iPad and the Duo's inner display, vertical bar on its outer display. Requires iOS 18 with native bars, iOS 15 with web bars or without sections. Duo support requires the iOS 27.1 SDK. |
| iPad sidebar | Opens at launch only in regular-width landscape windows. Users can collapse or reopen it. In narrower windows it opens over the page. |
| Android | Material 3 bottom bar below 600 CSS pixels, rail at 600 and above. Placement updates on resize, rotation, and folding. |
| Android separating hinge | Vertical: controls stay in the left pane. Horizontal: rail stays above the hinge, bottom bar below it. |
| Badges | iOS displays numbers as text. Android displays numbers as nonnegative integers and strings as text. `null` clears either. |

The iOS page draws edge to edge under the status bar, tab bar, and sidebar. Native-context safe-area insets and `--radical-safe-area-*` variables describe the space clear of bars. `safeAreaStyle` exposes these values for page layout.

- Android native bars paint through the system gesture inset.
- Rails also paint through the status-bar inset.
- Items stay inside the system insets.
- Android keeps a window-sized CSS viewport.
- Safe-area insets include navigation controls and update with the keyboard.
- Hidden routes remove navigation controls and their insets.

## Effect API

`@akshatowo/radical/effect/react` exports the same hook state with Effect-returning actions. `TanStackSections` is also exported from `@akshatowo/radical/effect/tanstack-start-client`.

| Export from `@akshatowo/radical/effect/client` | Contract |
| --- | --- |
| `makeSections(sections, initialLocation, navigate, initialHidden?, ownership?)` | Effect that creates an isolated controller. Locations are `{ href, pathname }`: full URL for memory, decoded pathname for ownership. |
| Controller | `snapshot()`, `destination(id)`, `select(id)`, `setBadge(id, value)`, `update(location, hidden?)`, and `subscribe(listener)`. Subscription returns cleanup. |
| `sectionOwnership(sections, caseSensitive = true, normalizePathname?)` | Compiles a matcher. Default normalization leaves paths unchanged. Original declarations remain navigation destinations. |
| `Sections`, `sectionsLayer(controller)` | Service and layer for `selectSection(id)` and `setSectionBadge(id, value)` Effects. |

- `tanstackSections(router, sections)` from the Effect TanStack entry point returns `{ controller, mount }`. `mount` requires `Bridge` and returns cleanup.
- The adapter applies the router's path normalization and case setting to ownership and transition checks.
- React's `TanStackSections` manages mounting and cleanup.
