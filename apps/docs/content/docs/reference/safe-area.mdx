---
title: "Safe-area API"
description: "Initial document CSS, component state, and scoped subscriptions."
---

`SafeArea` has `top`, `right`, `bottom`, and `left`. Each inset is finite, nonnegative, and measured in CSS pixels. Insets exclude keyboard height.

`safeAreaStyle(context, mode = "remote")` returns `--radical-safe-area-top`, `--radical-safe-area-right`, `--radical-safe-area-bottom`, and `--radical-safe-area-left`. Remote native context produces pixel strings. Browser context and bundled mode produce `env(safe-area-inset-*, 0px)` values for stable hydration.

`watchSafeArea(receive)` is an Effect subscription requiring `Bridge | Scope`. Acquisition returns the cleanup function and registers it for scope closure. Native events use `radicalSafeArea`; malformed inset events are ignored. Browser observation measures CSS `env()` insets and listens for resize changes.

`useSafeArea()` returns the provider's initial safe area and live changes after mount. It returns the insets directly, without loading or error state.

Native shells update CSS variables at document start and on inset changes. Android uses a layout viewport that resizes for the keyboard. iOS scrolls the focused input into view. The safe area does not become the keyboard height. No capability flag or extra dependency is required for the shell's safe-area handling.

`safeAreaStyle` is exported from `radical/client`, `radical/server`, and `radical/native-context`. `watchSafeArea` is exported from `radical/client`; `useSafeArea` is exported from `radical/react`.
