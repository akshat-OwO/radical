## Plain API

`hapticImpact(style?)`, `hapticNotification(type)`, and `hapticSelection()` from `@akshatowo/radical/client` return `Promise<void>`. `useHapticFeedback()` exposes feedback callbacks.

## Effect API

The contracts below use `@akshatowo/radical/effect/client`. See the [Effect API guide](/docs/guides/effect-api) for runtime composition.

Native enablement is `internalPlugins.haptics`. The dependency is `@capacitor/haptics@8.0.2`. No runtime permission prompt is required.

| Client export | Arguments | Result |
| --- | --- | --- |
| `hapticImpact(style?)` | `"LIGHT"`, `"MEDIUM"`, or `"HEAVY"`. Default `"MEDIUM"`. | Effect of void |
| `hapticNotification(type)` | `"SUCCESS"`, `"WARNING"`, or `"ERROR"` | Effect of void |
| `hapticSelection` | Effect value with no arguments | Effect of void |

These Effects require `Bridge | BrowserHaptics`. `hapticsLive(effect)` supplies `BrowserHapticsLive`. `BrowserHaptics` provides injectable `vibrate(pattern)` behavior. `ImpactStyleSchema` and `NotificationTypeSchema` validate inputs. Their types are `ImpactStyle` and `NotificationType`.

| Browser result | Behavior |
| --- | --- |
| Vibration available | Approximate patterns |
| Missing API or `vibrate` returns false | Successful no-op |
| Exception | `HapticFeedbackFailed` with `cause` |
| Hardware support | Success does not prove vibration; also applies to native devices |

| Error | Meaning |
| --- | --- |
| `BridgeError` | Transport or schema failure; invalid style or notification input produces `BridgeDecodeError` |
| `HapticFeedbackFailed` | Browser vibration exception; carries `cause` |

`useHapticFeedback()` exposes `light`, `medium`, `heavy`, `success`, `warning`, `error`, `selection`, and `impact`, plus action state. The failure field is `failure`; `error()` is an action. A completed action sets `value` to `true`.

| Feedback | Native haptics | Native haptics | Vibration API or successful no-op |
