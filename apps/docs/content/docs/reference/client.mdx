- `@akshatowo/radical/client` exports the Plain API.
- Bridge operations return Promises and reject with tagged error classes. `localNativeContext()` returns `NativeContext` synchronously, and `mountNativeContext()` returns `void`.
- Offline registration returns a Promise because service-worker registration is asynchronous.
- React hooks provide state and callbacks from `@akshatowo/radical/react`.

## Runtime ownership

`createRadicalRuntime()` returns a handle with `dispose(): Promise<void>`. `RadicalProvider` creates one runtime per provider, or accepts a caller-owned `runtime`.

`useRadicalRuntime()` retrieves that handle. `createPluginClient(manifest, runtime)` and generated `createPlugins(runtime)` share the provider's bridge.

Standalone calls share a lazy default runtime.

Disposal interrupts pending runtime commands and waits for resource cleanup. The [Effect API](/docs/guides/effect-api) can run typed programs against the same runtime.

## Lifecycle and bundled requests

| Export | Contract |
| --- | --- |
| `detectRuntime()` | Synchronous `"browser"`, `"android"`, or `"ios"`; SSR reports browser |
| `registerOffline({ production, mode?, base? })` | `Promise<void>`; registers the worker only in a production browser with service-worker support and remote mode. Call it from the [client entry](/docs/getting-started/installation#register-the-offline-worker) |
| `shouldRegister({ production, browser })` | Conjunction of the two flags |
| `createRadicalFetch(config)` | Fetch-compatible function routing eligible bundled requests to the configured origin |
| `localNativeContext()` | Browser context before mount, then validated injected context |
| `mountNativeContext()` | Marks the mount handoff and applies native safe-area CSS variables |
| `browserContext()` | Browser platform, zero insets, null shell version |
| `safeAreaStyle(context?, mode?)` | Document CSS variables |
| `isNotificationScheduleResult(value)` | Type guard for notification hook results |

## Capabilities

- `getDeviceInfo()`, camera and permission operations, file selection, intents, haptics, network status, location, Google sign-in, notifications, and data protection return Promises.
- Their result types match the capability hooks. `watchLocation(receive, onError, options?)` returns a function that stops the watch.
- Scoped video sessions, network subscriptions, and safe-area subscriptions are available through the React hooks or Effect API.

## Failures

- `BridgeError` is `BridgeUnavailable | BridgeCallFailed | BridgeDecodeError`.
- Each error retains its `_tag` and class identity.
- Common capability errors include `PermissionDenied`, `Cancelled`, and `Unavailable`.
- Registration failures use `ServiceWorkerRegistrationError`; fetch failures use `RequestFailed`.

Services, layers, Streams, schema codecs, and `registerOfflineEffect` are exported from `@akshatowo/radical/effect/client`.

## App update policy

`createRadicalFetch(config, store?)` recognises Radical's marked 426 responses from the configured bundled API origin. It sets the update state to `required` and returns the original response without consuming its body. Other origins and ordinary browser fetches retain their normal behavior.

`fetchAppUpdate(createRadicalFetch(config), store?)` fetches the startup policy and returns a Promise of `{ status: "current" | "required" | "unknown", storeUrl: string | null }`. A failed fetch rejects with `RequestFailed`; the previous state remains unchanged. A required state persists until the app reloads, including when an earlier startup request finishes later.

`createAppUpdateStore(initialState?)` creates an isolated controller.

Fetch helpers, hooks, screens, and boundaries accept the same optional store. Omitting it uses the shared client controller. Initial state defaults to `unknown` with no store URL.

The Effect API exports `fetchAppUpdate` and `radicalFetch(config, input, init?, store?)` from `@akshatowo/radical/effect/client`. `radicalFetch` requires `RadicalFetchEnvironment`; `RadicalFetchEnvironmentLive` supplies browser transport and injected shell context. Tests can supply an in-memory layer.
