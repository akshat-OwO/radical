---
title: "Radical config"
description: "Every field accepted by RadicalConfigSchema in @akshatowo/radical/vite."
---

Radical accepts a config object passed to `radical(config)` in Vite config. There is no separate `radical.config` file loader. `RadicalConfig`, `RadicalConfigSchema`, `validateConfig`, and `InvalidConfig` are exported from `@akshatowo/radical/vite`.

## App and delivery fields

| Field | Type | Default and constraints |
| --- | --- | --- |
| `version` | Nonempty string | App version shown in stores. Defaults to the app's `package.json` version. On iOS, one to three period-separated integers. |
| `build` | Positive safe integer | App build. Defaults to `1` when no CLI flag or environment variable is set. Android permits at most `2100000000`. |
| `appId` | `string`, required | Dot-separated segments. Each starts with a letter and contains letters, digits, or underscores. Identifies web cache storage and supplies native identifier defaults. |
| `appearance` | `"system"`, `"light"`, or `"dark"` | Defaults to `"system"`, which follows the device. `"light"` and `"dark"` pin the whole native shell. |
| `mode` | `"remote"` or `"bundled"` | Omitted means remote behavior. |
| `origin` | HTTP origin | Required in bundled mode. An exact `http:` or `https:` origin without path, trailing slash, query, or wildcard. In remote mode, overrides the recorded dev URL. |
| `allowlist` | Array of HTTP origins | Additional remote-mode document origins. Ports are significant. Bundled mode permits only its local document origin. |
| `devHost` | `string` | Letters, digits, dots, and hyphens. Defaults to the first external IPv4 address, then `127.0.0.1`. Controls the recorded URL, not Vite's bind address. |
| `name` | Nonempty string | Shared native display name. |
| `appName` | Nonempty string | Legacy fallback after `name`. |
| `android.name` | Nonempty string | Overrides the shared name on Android. |
| `android.packageId` | `string` | Defaults to `appId`. At least two dot-separated segments starting with a letter. Letters, digits, and underscores allowed. Java keywords forbidden. |
| `ios.name` | Nonempty string | Overrides the shared name on iOS. |
| `ios.bundleId` | `string` | Defaults to `appId`. At least two dot-separated segments containing letters, digits, or hyphens. |

Display names resolve as platform `name`, shared `name`, legacy `appName`, then `appId`. Remote iOS generation permits at most ten distinct server and allowlist hostnames.

A pinned appearance applies to:

- System bars
- Section bars and rails
- The keyboard
- System dialogs

The WebView's `prefers-color-scheme` follows the pinned appearance:

- Under `"light"`, `@media (prefers-color-scheme: dark)` does not match in the shell.
- A plain browser still follows the device setting.
- Appearance is build-time only.

Invalid `appearance` values return `InvalidConfig` with the `appearance` field path.

## Navigation fields

- `navigation.sections` enables section navigation with 2 to 5 sections.
- The first is the start section.
- See [Sections](/docs/reference/sections) for the config fields, validation, routing, and badges.

<Callout type="info">

Navigation options are available in `@akshatowo/radical` 0.3.0 and later.

</Callout>

| Field | Values | Default |
| --- | --- | --- |
| `navigation.bar.ios`, `navigation.bar.android` | `"native"`, `"web"` | `"native"` |
| `navigation.android.labels` | `"labeled"`, `"selected"`, `"unlabeled"` | `"labeled"` |
| `navigation.android.colors.container`, `.indicator`, `.badge` | Color | Material 3 defaults |
| `navigation.android.colors.icon.selected`, `.unselected` | Color | Material 3 defaults |
| `navigation.android.colors.label.selected`, `.unselected` | Color | Material 3 defaults |

- Color accepts `#RRGGBB`, `#AARRGGBB`, or `{ light, dark }` containing either format.
- With `appearance: "system"`, Android section bars resolve these pairs against the device setting.
- A pinned appearance selects the matching half. The unused half is accepted without error or warning.
- Invalid options return `InvalidConfig` with the field path.
- Web mode omits native bars and keeps system-only safe-area insets.
- See [bar and Android theme](/docs/reference/sections#bar-and-android-theme) for an example.

## Image fields

| Field | Type | Constraints |
| --- | --- | --- |
| `icon` | Path string or `{ image, backgroundColor? }` | Square PNG or JPEG, at least 1024 pixels per side. Relative to the app root. |
| `icon.image` | Nonempty path | Same constraints as string-form `icon`. |
| `icon.backgroundColor` | `#RRGGBB` | Optional opaque RGB background. |
| `splash.image` | Nonempty path | Square PNG or JPEG, at least 2732 pixels per side. Relative to the app root. |
| `splash.backgroundColor` | `#RRGGBB`, required with splash | Composites transparent source pixels. Shared by light and dark appearances. |

Omitting `splash` shows the Radical logo on a white background on iOS and Android, including with `appearance: "dark"`. Setting `splash` uses your image and background color in both light and dark appearances.

Invalid images produce `InvalidAsset`; asset-writing failures produce `AssetGenerationFailed`. These are generation failures, not client API exports.

## Plugin fields

| Field | Type | Meaning |
| --- | --- | --- |
| `plugins` | Array of `{ manifest, selector? }` | Custom manifest module paths. Disabled unless listed. |
| `plugins[].manifest` | Nonempty string | Module path relative to the app root. |
| `plugins[].selector` | JavaScript identifier | Named manifest export. Omitted selects the default export. |
| `pluginOptions` | Record of unknown values | Decoded by each enabled manifest's config schema, keyed by its config selector. |
| `internalPlugins` | Object of optional booleans | Enables internal capabilities. Implications take precedence over explicit false values. |

| Internal flag | Default | Implication |
| --- | --- | --- |
| `device`, `transitions` | `true` | None |
| `camera`, `videoStream`, `filePicker`, `intents`, `haptics`, `network`, `location`, `googleSignIn`, `dataProtection` | `false` | None |
| `notifications` | `false` | Enables `network` |
| `pushNotifications` | `false` | Enables `notifications`, then `network` |

## Internal plugin options

| Selector | Required fields when enabled |
| --- | --- |
| `Camera` | `usageDescription`, `photoLibraryUsageDescription` |
| `VideoStream` | `usageDescription` |
| `GoogleSignIn` | `webClientId`, `iosClientId` |
| `Location` | `usageDescription`; optional `precisePurposes` and `replaceNavigator` |

- Camera descriptions require non-whitespace text without invalid XML control characters.
- Shared camera purposes compose once into the iOS camera description.
- Location purposes follow the same text rules; see the [Location API](/docs/reference/location#config).
- Google identifiers match letters, digits, underscores, or hyphens followed by `.apps.googleusercontent.com`.

## Firebase fields

| Field | Type | Meaning |
| --- | --- | --- |
| `notifications.android.googleServices` | Nonempty path | App-owned Firebase JSON copied into the generated Android project. |
| `notifications.ios.googleServiceInfo` | Nonempty path | App-owned Firebase plist copied into the generated iOS project. |
| `notifications.ios.environment` | `"development"` or `"production"` | APNs entitlement. Defaults to `"development"`. |

- Firebase paths do not enable push by themselves.
- Missing runtime push configuration produces `MissingPushConfiguration`.
- Invalid main config produces `InvalidConfig`; manifest failures produce `InvalidPlugin` or `PluginDependencyConflict`.
