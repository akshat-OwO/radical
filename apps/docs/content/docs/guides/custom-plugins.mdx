---
title: "Add a typed native plugin"
description: "Enable a Schema-defined manifest and call its commands."
---

<Steps>
<Step>

### Define the manifest

Plugin authoring uses Effect Schema. Install `effect` directly with `pnpm add effect@^4.0.5` before writing a manifest. Calling an enabled plugin through the Plain API does not require importing Effect.

Copy the [Echo manifest](https://github.com/akshat-OwO/radical/blob/main/apps/example/plugins/echo.ts), following the [manifest contract](/docs/reference/plugins).

</Step>
<Step>

### Enable the plugin

Configure your manifest:

```ts
plugins: [{ manifest: "./plugins/echo.ts" }],
pluginOptions: { Echo: { prefix: "Native: " } },
```

</Step>
<Step>

### Generate declarations

Include `.radical/plugins.d.ts` in `tsconfig.json` before running:

```sh
pnpm exec radical typegen
```

[Regenerate shells](/docs/guides/run-on-a-device#prerequisites) after manifest or native-source changes.

</Step>
<Step>

### Call the command

Call the Plain API from your lifecycle or event handler:

```ts
import { plugins } from "virtual:radical/plugins";
import { EchoRejected } from "./plugins/echo";

try {
  const result = await plugins.echo.echo({ text: "hello" });
  console.log(result.text);
} catch (error) {
  if (error instanceof EchoRejected) {
    console.log(error.reason);
  }
}
```

Inside a provider, use `createPlugins(useRadicalRuntime())` to share its runtime. For typed composition, import `plugins` from `virtual:radical/effect/plugins` and follow the [Effect API guide](/docs/guides/effect-api).

You receive the native Echo result or handled rejection.

</Step>
</Steps>

See the [bridge sequence](/docs/explanation/bridge).
