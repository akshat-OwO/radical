---
title: "Switch to bundled mode"
description: "Package the UI while keeping server functions on your API origin."
---

<Steps>

<Step>

### Select bundled delivery

Set `mode: "bundled"` and `origin` to your API's HTTP origin in `vite.config.ts`:

```ts
const config = {
  appId: "dev.example.app",
  mode: "bundled",
  origin: "https://api.example.com",
} satisfies RadicalConfig;
```

Pass the same config to `tanstackStart(tanstackStartOptions(config))` and `radical(config)` from `radical/tanstack-start`.

</Step>

<Step>

### Configure Start requests

In `src/start.ts`, use the virtual config for SSR and server-function fetch:

```ts
import { createStart } from "@tanstack/react-start";
import { createRadicalFetch } from "radical/client";
import { createRadicalRequestMiddleware } from "radical/tanstack-start-server";
import { config } from "virtual:radical/config";

export const startInstance = createStart(() => ({
  defaultSsr: config.mode !== "bundled",
  requestMiddleware: [...createRadicalRequestMiddleware()],
  serverFns: { fetch: createRadicalFetch(config) },
}));
```

</Step>

<Step>

### Wrap the API handler

On the API server, wrap the Start handler with `withBundledRequests` from `radical/tanstack-start-server`. Keep this explicit opt-in when you switch modes:

```ts
import {
  createStartHandler,
  defaultStreamHandler,
} from "@tanstack/react-start/server";
import {
  offlineHandler,
  withBundledRequests,
} from "radical/tanstack-start-server";

export default {
  fetch: withBundledRequests(
    createStartHandler(offlineHandler(defaultStreamHandler))
  ),
};
```

</Step>

<Step>

### Prepare hydration and offline startup

In the root route loader, use `Effect.runPromise(localNativeContext())` for bundled mode. Keep the remote-mode server-function loader for remote mode.

For bundled rendering, wrap `<Outlet />` in TanStack Router's `<ClientOnly>`.

Apply `safeAreaStyle(nativeContext, config.mode)` to the document. In a mount effect, run `Effect.runSync(mountNativeContext())` for bundled mode.

Pass `mode: config.mode` to `registerOffline` so bundled mode skips worker registration.

For other API requests, use `createRadicalFetch(config)`. Keep initial route loaders independent of the API if the app must start without it.

</Step>

<Step>

### Regenerate the shells

Regenerate with `pnpm exec radical android` or `pnpm exec radical ios` from the app directory. To generate without launching, add `--generate-only`.

</Step>

</Steps>

To serve the API locally, build the app and run `pnpm exec vp preview --host 0.0.0.0 --port 4173` from the app directory. Set `origin` to the address the device can reach.

<Callout type="warning" title="Keep CORS at the API handler">
  If you customize Vite CORS, use `cors: false` or an origin callback returning
  `false` for both bundled origins. Static origin lists can consume preflights
  before `withBundledRequests`.
</Callout>

Keep Start's `dist/client`, `_shell.html`, and Vite base `/`. The [example root route](https://github.com/akshat-OwO/radical/blob/main/apps/example/src/routes/__root.tsx) has the complete mode-dependent setup. For authentication constraints, read [Delivery modes](/docs/explanation/delivery-modes).
