---
title: "Keep visited routes available offline"
description: "Add remote-mode snapshots and an offline fallback."
---

See the [snapshot lifecycle](/docs/explanation/offline-caching).

<Tabs items={["Remote", "Bundled"]}>
<Tab value="Remote">

<Steps>
<Step>

### Mark routes

Set eligible routes' static data:

```ts
staticData: { radical: { offline: true } },
```

</Step>
<Step>

### Configure the server

Wrap `defaultStreamHandler` with `offlineHandler` from `@akshatowo/radical/tanstack-start-server` in `src/server.ts`.

</Step>
<Step>

### Add the fallback

Create `public/offline.html`.

</Step>
<Step>

### Register the worker

Register from the [client entry](/docs/getting-started/installation#register-the-offline-worker), after hydration:

```ts
void registerOffline({
  mode: config.mode,
  production: import.meta.env.PROD,
  base: import.meta.env.BASE_URL,
});
```

</Step>
<Step>

### Verify snapshots

After worker activation in a production build, visit each exact URL through document navigation, then stop the UI server.

| Reopen                              | Expected result  |
| ----------------------------------- | ---------------- |
| Visited URL, including query string | Stored document  |
| Unvisited URL                       | Offline fallback |

</Step>
</Steps>

<Callout type="warning">
  Serve over HTTPS or trustworthy localhost. Plain HTTP LAN addresses cannot
  register workers.
</Callout>

</Tab>
<Tab value="Bundled">

[Package the UI](/docs/guides/bundled-mode); do not register the remote worker.

</Tab>
</Tabs>

See shell startup checks for [Android](https://github.com/akshat-OwO/radical/blob/main/docs/verification/android-offline.md) and [iOS](https://github.com/akshat-OwO/radical/blob/main/docs/verification/ios-offline.md).
