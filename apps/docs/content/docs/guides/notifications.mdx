---
title: "Schedule a local notification"
description: "Schedule a reminder, cancel it, and update the app badge."
---

<Steps>

<Step>

### Enable local notifications

Install `@capacitor/local-notifications@8.3.1`, `@capawesome/capacitor-badge@8.0.4`, and `@capacitor/network@8.0.1`.

Set `internalPlugins.notifications: true` and regenerate both shells.

</Step>

<Step>

### Request display permission

Call `useNotificationPermission()` and `useNotifications()` from `radical/react`.

From a user action, call `permission.request()`.

</Step>

<Step>

### Schedule a reminder

To schedule a reminder, call:

```ts
notifications.schedule({
  id: 22,
  title: "Your report is ready",
  delaySeconds: 5,
  route: "/reports",
});
```

</Step>

<Step>

### Cancel, badge, or navigate

To cancel that reminder, call `notifications.cancel(22)`.

If the launcher supports badges, call `notifications.setBadge(1)` or `notifications.clearBadge()`.

To navigate on a notification tap, install the app-scoped watcher described in [Handle notification taps](/docs/guides/notification-navigation).

</Step>

</Steps>

Keep the browser page open for browser reminders. For native push, follow [Configure Firebase push](/docs/guides/firebase). See [Notifications reference](/docs/reference/notifications) for inputs and errors.

## Request exact alarms on Android

<Steps>

<Step>

### Check exact-alarm access

Call `useExactAlarmPermission()` from `radical/react`.

Wait for the initial check to finish. If `exactAlarms.value` is `"denied"`, offer a separate button that calls `exactAlarms.request()`.

</Step>

<Step>

### Grant access in settings

In Android's **Alarms & reminders** settings, allow exact alarms and return to your app.

Wait for the request to return `"granted"` before enabling the schedule button.

</Step>

<Step>

### Schedule and inspect the result

From the schedule button's click handler, call `notifications.schedule()` with `delaySeconds: 5`. Radical computes the scheduled time for this call.

Inspect `notifications.value` after scheduling. If `value.warning?.code` is `"OS-PLUG-LNOT-0017"`, tell the user that Android scheduled an inexact alarm.

After the user grants access, schedule that reminder again to replace the inexact alarm.

</Step>

</Steps>

Request access before scheduling so time spent in Android settings does not consume the reminder's delay. To refresh the setting after a user changes it outside your app, call `exactAlarms.check()`.

See [Exact alarms and schedule results](/docs/reference/notifications#exact-alarms-and-schedule-results) for Android defaults, exceptions, and policy limits.
