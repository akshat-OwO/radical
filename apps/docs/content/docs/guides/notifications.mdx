---
title: "Schedule a local notification"
description: "Schedule a reminder, cancel it, and update the app badge."
---

<Steps>
<Step>

### Enable notifications

Apply [capability setup](/docs/guides/run-on-a-device#prerequisites) with `internalPlugins.notifications: true`:

```sh
pnpm add @capacitor/local-notifications@8.3.1 @capawesome/capacitor-badge@8.0.4 @capacitor/network@8.0.1
```

</Step>
<Step>

### Request permission

Connect a user action to:

```ts
const permission = useNotificationPermission(); // radical/react
const notifications = useNotifications();
permission.request();
```

</Step>
<Step>

### Schedule a reminder

Call from a button after permission is granted:

```ts
notifications.schedule({
  id: 22,
  title: "Your report is ready",
  delaySeconds: 5,
  route: "/reports",
});
```

You see the reminder when the OS delivers it.

</Step>
<Step>

### Add controls

Connect the required actions:

| Action | Call or guide |
| --- | --- |
| Cancel | `notifications.cancel(22)` |
| Badge, where supported | `notifications.setBadge(1)`, `.clearBadge()` |
| Tap navigation | [App-scoped watcher](/docs/guides/notification-navigation) |
| Native push | [Firebase setup](/docs/guides/firebase) |

</Step>
</Steps>

Keep the page open for browser reminders. See [inputs and errors](/docs/reference/notifications).

## Request exact alarms

<Tabs items={["Android", "iOS"]}>
<Tab value="Android">

<Steps>
<Step>

### Request access

After the initial check, offer a separate request button only for `"denied"`:

```ts
const exactAlarms = useExactAlarmPermission(); // radical/react
// Request button:
exactAlarms.request();
// Refresh after external settings changes:
exactAlarms.check();
```

</Step>
<Step>

### Return from settings

Allow **Alarms & reminders**, then wait for `"granted"` before enabling scheduling.

</Step>
<Step>

### Schedule again

Call `notifications.schedule()` from the button with `delaySeconds: 5`.

| Result | Action |
| --- | --- |
| `value.warning?.code === "OS-PLUG-LNOT-0017"` | Tell the user the alarm is inexact |
| Access granted after inexact scheduling | Reschedule the same reminder to replace it |

</Step>
</Steps>

<Callout type="warning">
  Request access before scheduling; time in settings consumes an existing
  reminder's delay.
</Callout>

</Tab>
<Tab value="iOS">

Use display permission above; Android exact-alarm settings do not apply.

</Tab>
</Tabs>

See [exact-alarm limits](/docs/reference/notifications#exact-alarms-and-schedule-results).
